1. The Deadlock (Phase 2):
In the `deadlock_simulation.py` script, explain step-by-step how the "Circular Wait" condition occurred between Model A and Model B.

Model A holds GPU 0 and waits for GPU 1. Model B holds GPU 1 and waits for GPU 0. neither model releases the GPU it already has, so they wait for each other and cannot finish. this is the circular wait.

2. The Solution (Phase 3):
By changing the code in `deadlock_avoidance.py` so that Model B also requests GPU 0 first, how did this specifically break the "Circular Wait" condition?

because both models request GPU 0 before GPU 1, only one model can take GPU 0 first. the other waits without holding GPU 1. the first model can get GPU 1, finish its work, and release both GPUs. this breaks the circular wait.

Starvation vs Deadlock (Phase 4): Based on the results from `starvation_sim.py`: - How is the final output of the Starvation script fundamentally different from the Deadlock script you ran in Phase 2? - In your own words, explain how a process scheduler could use a technique called "Aging" to help the `Polite_Model` get a fair share of CPU time.

in starvation, the greedy model can still make progress while the polite model keeps waiting or gets very little work done. in deadlock, both models are stuck and neither can continue.
aging means the scheduler slowly raises the priority of a process that waits for a long time. so the Polite_Model eventually gets a turn instead of always losing to a higher priority process.

4. Deadlock Detection & Recovery (Phase 3.3):
- How did the `timeout` parameter simulate the Deadlock Detection mechanism of an Operating System?
- When the Deadlock was detected, what exact step did Model A take to perform "Recovery" and allow the rest of the system to continue?

the timeout stops Model A from waiting forever for GPU 1. if the lock is still unavailable when the time runs out, the script treats it as a possible deadlock. a timeout is a warning, because a long wait alone does not always prove deadlock.
Model A then releases GPU 0 and gives up its current work. Model B can get GPU 0, finish, and release its resources, so the system can continue.
